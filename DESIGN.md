# CraftCV design system

A daylight-first desktop workspace for developers reviewing an application. The color strategy is restrained: light blue-tinted workspace layers, near-white content surfaces, and one cyan accent reserved for primary actions, focus, and selected states. Dark mode uses the same cyan accent over near-black blue-tinted layers.

System sans-serif throughout. 14 px base; 32 px primary heading, 14.5 px section heading. Small labels support the task hierarchy without competing with source text. Mono is reserved for file paths and source excerpts.

HeroUI theme tokens live in `src/renderer/styles.css`. The light accent is `oklch(78% 0.16 225)`, the background is `oklch(97.02% 0.02 225)`, and neutrals carry a visible blue tint (chroma 0.02–0.04 at hue 225). Controls use a 6 px radius and major workflow surfaces use 12 px. One-pixel separators communicate structure; shadows are reserved for transient overlays and pinned alerts.

The navigation sidebar floats 10 px in from the window edges (rounded 14 px, a soft shadow, `--surface`), using CraftCV's compact floating layout; it collapses to a 56 px icon rail with the header toggle or ⌘B. A translucent sticky header sits above the content. Both stay visually quieter than the task. Product pages use functional titles and short descriptions. A new application uses five focused pages: Job, Requirements, Your CV, Projects, and Review. The tracker is a compact progress row using unmodified HeroUI buttons over a hairline baseline. Most steps use a single 820 px reading column with a plain heading, sparse dividers, and one forward action. Requirements expands to the full content width. Before analysis, the original posting uses that width and Analyse the job sits beside View posting. Opening AI setup introduces the right pane; the live process and extracted requirements remain there beside the source, separated by one hairline. The comparison stacks in source-first order when its content width falls below 760 px. There is no enclosing workflow card, repeated step badge, or tinted footer bar. HeroUI fields, tabs, buttons, and disclosures keep their library styling; CraftCV CSS controls only page composition and owned content wrappers. Evidence suggestions keep only the containment needed to distinguish editable claims. Local data and privacy behavior remain visible without interrupting the task.

HeroUI v3 provides the shared Button primitive with CraftCV mappings for primary, outline, ghost, danger, and compact states. Form controls use accessible labels, keyboard focus, live error/status regions, and explicit empty/loading states. An action shows pending feedback on its own button or beside the affected content; the header has navigation and theme only. Long local scans keep detailed progress in the review step. Motion is limited to short interaction transitions and removed when reduced motion is preferred.

## Document workspace

The Documents library puts a visible template gallery above the compact saved-document list. All templates share one grid of compact cards: each card is itself the button, showing a real miniature render, the name, and a one-line credit (CraftCV, Jake's Resume · MIT, RenderCV · MIT); the description is in its tooltip. This makes the choice inspectable without a modal or hidden menu. Blank document and Import CV remain compact page actions. Choosing a template creates a normal editable local document. The editor keeps title, save status, exports, formatting toolbar, and zoom controls above a scrollable neutral canvas. Rarely used inserts (dated line, table, rule, page break) sit in one Insert menu to keep the toolbar to a single row at common widths; find and replace and page setup open as slim bars under the toolbar, like the link form, and the heading outline opens as a 220 px panel beside the pages. An A4-width white document uses Arial by default with heading/list/table styles matching the export model. Users can select Georgia, Times New Roman, or Verdana, adjust size and color, and apply common text formatting. All toolbar actions have accessible labels, active states, and keyboard-compatible controls.
